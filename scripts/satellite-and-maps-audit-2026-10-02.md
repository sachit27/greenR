# greenR satellite mosaics and map access: implementation audit

**Date:** 2026-10-02. **Status:** code and smoke tests completed; field accuracy not established.

The heat-priority online path now pages Planetary Computer STAC results (50 items per page, default maximum 12 pages), signs assets, applies Sentinel-2 SCL and Landsat QA_PIXEL masks, and fills each output pixel from the first clear valid observation. It stops if fewer than 99.5% of AOI cells have valid observations, unless the caller explicitly changes `satellite_min_coverage`. It records the contributing scene IDs, dates, cloud cover, pixel contributions, coverage, page count, and a source-index TIFF. Old single-scene cache files are not reused. Source rasters are read with a two-pixel crop margin to avoid losing boundary cells during reprojection.

**Comparison with the previous single-scene practice.** A live Sentinel-2 test at a tile seam near 9°E, 47.4°N (bbox 8.995,47.400–9.005,47.401; 2025-08-08/09) required two scenes. The lowest-cloud scene supplied 480 of 912 output cells (52.6%). The second supplied 432 cells, bringing the final coverage to 100%. This demonstrates removal of one concrete coverage failure. An offline test also verifies that a second STAC page can fill a spatial gap and that hitting the page limit with incomplete coverage stops before scoring. It does **not** demonstrate improved NDVI accuracy against independent reference data.

**Live source integration.** In a separate 0.001° × 0.001° area in central Zurich (8.530–8.531°E, 47.370–47.371°N), the 2025-06-01/08-31 query returned complete NDVI (116 10 m cells) and LST (20 30 m cells) mosaics. The CHMv2 source yielded 216 valid output cells (maximum 17.89 m), and the remote GBA GeoParquet query returned two footprints. See `live_source_metrics.json` in the accompanying download. This is a source and spatial plumbing check, not a full priority-index validation or a comparison with independent field observations.

**Map access.** The default basemap is Esri Gray, verified with a live key-free tile request (HTTP 200) and service metadata. Its attribution was updated from the service's current copyright text. CARTO now requires a basemap key for unwatermarked tiles; selecting `options(greenR.basemap = "carto")` without `CARTO_API_KEY` gives an actionable error. The legacy H3 extrusion and pitched linestring exporters now use MapLibre by default, with no Mapbox token. `accessibility_mapbox()` still needs a Mapbox token because it calls the Mapbox Isochrone API; its error points users to the token setup and the Mapbox-free `accessibility_greenspace()` alternative. The README explains the setup, and generated HTML was checked for the absence of Mapbox and CARTO URLs in key-free mode.

**Remaining limits.** The first-clear mosaic mixes dates and possibly sensors/orbits within the query window; it is a screening layer, not simultaneous land surface temperature. Scenes are ranked by scene-level cloud cover **within each page**, not by AOI cloudiness across the entire catalog. Nearest-neighbor alignment avoids interpolation across QA gaps but can shift individual source pixels at seams. A 20-million-cell target-grid cap protects memory; source reads and repeated coverage checks may still be costly. The default 99.5% AOI threshold does not guarantee that every analysis hex has high valid-pixel coverage; empty units fail in the existing zonal checks. Neither CHM nor GBA was checked against local LiDAR/building surveys. A multi-city, multi-season accuracy study and independent reference data are needed before claiming field validity or research-grade accuracy.

**Reproduce.** Run `Rscript scripts/live-source-integration-2026-10-02.R /tmp/greenR-source-audit` from the package root with network access. Run `devtools::test()` for deterministic unit and rendering checks. No CRAN version or package release was created.
